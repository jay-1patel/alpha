# Multi-Vertical Support Platform — Full Record (updated 2026-09-30)

Bottom line: 5 tenants across 5 verticals (ecommerce, IT/software, tours/travel,
banking, finance) run on one codebase. Behavior comes from data, not code.
Every phase has a repeatable verification suite, all green.

Tenants:
  troogood          (ecommerce)     — live reference brand, commerce fully on
  leewaysoftech     (it_software)   — commerce off, quote/callback on
  wanderly          (tours_travel)  — commerce off, enquire/callback on
  meridianbank      (banking)       — compliance guardrails, fraud escalation
  northwindcapital  (finance)       — advisory guardrails, notice escalation

Architecture decisions (D1-D5):
  D1  backend/ is the serving stack; root routing/ is the live webhook layer;
      kb/ is the retrieval library. backend/routing/ (dead copy) DELETED in 7b.
  D2  SQLite only. JSON fields are TEXT storing JSON.
  D3  Conversation state extends state_manager.py (no parallel store).
  D4  Thin substrate: in-memory cache (no Redis), 3+ step flow runner.
  D5  .env holds only secrets + deployment; all behavior from the profile.
  Merge order: vertical defaults -> clients/<id>/config.json -> DB override
  (pydantic-validated, versioned, rollbackable). NOTE: published DB versions
  SHADOW defaults.py — republish every tenant after touching defaults.
